🔥 문제 상황

🔍 원인 분석

프레임 단위(Single-Frame) 좌표값만 즉시 딥러닝 모델의 입력으로 넣어, 시계열 노이즈 흡수력이 부족했음.

💡 해결 방안

1차적으로 Landmark 좌표 벡터에 이동평균 필터(Moving Average Filter)를 적용하고, 제스처 최종 판정 단계에 윈도우 기반 큐(Queue)를 두어 연속 복수 프레임의 결과가 일치할 때만 트리거되도록 Debounce 로직 구현.

Trouble Shooting: 대량의 웹 데이터 수신 시 STM32 데이터 유실 현상

🔥 문제 상황

웹 대시보드에서 마우스를 빠르게 움직여 연속적인 좌표 패킷을 전송할 시, RC카 모터 반응이 끊기거나 멈추는 오작동 발생.

🔍 원인 분석

ESP32가 수신한 패킷을 UART를 통해 STM32로 쏴줄 때, STM32가 인터럽트 방식으로만 처리하다 보니 수신 속도를 따라가지 못해 Overrun Error(ORE) 및 버퍼 오버플로우가 발생하여 데이터 유실됨.

💡 해결 방안

STM32 내부 UART 수신 아키텍처를 인터럽트 방식에서 DMA Circular Mode 방식으로 전면 변경. 수신 버퍼링을 하드웨어 레이어에서 처리하도록 유도하고 링 버퍼(Ring Buffer) 파싱 코드를 설계하여 CPU 부하를 제거함으로써 패킷 유실률 0% 달성.
